# Развертывание серверной версии «Вектор»

## Что входит в серверный контур

- Fastify API и раздача production-сборки React;
- PostgreSQL 17 для задач, документов, справочников, пользователей, сообщений, уведомлений и отчетов;
- отдельная таблица `entity_files` для двоичного содержимого вложений;
- bcrypt-хеши паролей, серверные роли и права;
- случайные сессии в `HttpOnly` cookie и ограничение попыток входа;
- SSE-обновления данных в других открытых клиентах;
- серверный аудит и автоматические SQL-миграции;
- экспорт резервной копии и перенос существующей IndexedDB.

## Требования к VPS

- Ubuntu 24.04 LTS или Debian 12;
- 2 vCPU, 4 ГБ RAM, от 30 ГБ SSD;
- Docker Engine с Compose plugin;
- домен и HTTPS-сертификат для рабочего использования.

## Подготовка чистого Ubuntu VPS

```bash
sudo apt update
sudo apt install -y ca-certificates curl git
curl -fsSL https://get.docker.com -o /tmp/get-docker.sh
sudo sh /tmp/get-docker.sh
sudo usermod -aG docker "$USER"
```

Перезайдите по SSH, затем проверьте `docker --version` и `docker compose version`. Разместите проект, например, в `/opt/vector`, и перейдите в этот каталог.

## Первый запуск

Все команды выполняются из корня проекта, где лежат `package.json`, `pnpm-lock.yaml` и `compose.yaml`.

Обычная production-сборка `pnpm build` уже настроена на серверное хранилище и обращается к API по относительному адресу `/api`. Команда `pnpm run build:local` предназначена только для автономной демонстрации с IndexedDB и не должна публиковаться как многопользовательская серверная версия.

```bash
cp .env.server.example .env
openssl rand -base64 36
```

В `.env` задайте уникальные `POSTGRES_PASSWORD` и `COOKIE_SECRET`. Для первой проверки по HTTP оставьте `COOKIE_SECURE=false`. После подключения HTTPS измените значение на `true`.

```bash
docker compose up -d --build --force-recreate
docker compose ps
docker compose logs --tail=100 app
curl http://127.0.0.1:8080/api/health
```

Флаг `--force-recreate` важен после исправления режима хранения: он гарантирует, что VPS не продолжит раздавать старый frontend-контейнер с локальной IndexedDB.

После обновления удалённые пользователи не создаются повторно при перезапуске. Если пользователь всё же появляется снова, проверьте, что открывается адрес серверной версии, а не `http://127.0.0.1:5173`, и что на VPS не выполняется восстановление старой резервной копии.

Первичная база создается автоматически. Начальный администратор: пользователь «Иванов И. И.», пароль `123`. Сразу после входа измените пароль администратора.

Контейнер доступен только локально на порту `127.0.0.1:8080`; PostgreSQL наружу не публикуется.

## Установка системного Nginx и HTTPS

```bash
sudo apt update
sudo apt install -y nginx certbot python3-certbot-nginx ufw
sudo cp deploy/vector-vps.nginx.conf /etc/nginx/sites-available/vector
sudo sed -i 's/vector.example.ru/ВАШ.ДОМЕН/g' /etc/nginx/sites-available/vector
sudo ln -s /etc/nginx/sites-available/vector /etc/nginx/sites-enabled/vector
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d ВАШ.ДОМЕН
```

После успешного выпуска сертификата установите в `.env` значение `COOKIE_SECURE=true` и примените его:

```bash
docker compose up -d
sudo certbot renew --dry-run
```

Firewall:

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
```

## Перенос данных из текущего браузера

1. Откройте серверную версию в браузере, где использовался локальный вариант.
2. Войдите администратором.
3. Откройте «Настройки → Данные и резервные копии».
4. Нажмите «Перенести в PostgreSQL» и подтвердите действие.
5. Проверьте задачи, документы, справочники, пользователей, чат и вложения после обновления страницы.

Перенос выполняется как upsert: совпадающие идентификаторы обновляются, остальные записи добавляются. IndexedDB не очищается. Пользователям без доступного пароля назначается временный пароль `123`, который следует заменить.

## Резервное копирование

```bash
chmod +x deploy/backup.sh
./deploy/backup.sh /srv/vector-backups
```

Храните копии вне VPS и проверяйте восстановление на отдельном экземпляре:

```bash
gunzip -c /srv/vector-backups/vector-YYYYMMDD-HHMMSS.sql.gz | docker compose exec -T postgres psql -U vector -d vector
```

Встроенная JSON-копия удобна для переноса через интерфейс, но не заменяет полный дамп PostgreSQL.

### Как посмотреть содержимое файла backup

Файл, созданный `backup.sh`, имеет имя вида `vector-YYYYMMDD-HHMMSS.sql.gz`. Это сжатый текстовый SQL-дамп, а не файл Word или Excel. Его можно безопасно посмотреть без восстановления в базу:

```bash
# Выводит первые 80 строк выбранного дампа в терминал, не меняя базу данных.
gunzip -c /srv/vector-backups/vector-YYYYMMDD-HHMMSS.sql.gz | head -n 80

# Распаковывает копию дампа в обычный .sql-файл для просмотра в текстовом редакторе.
# Исходный .sql.gz-файл при этом остается без изменений.
gunzip -c /srv/vector-backups/vector-YYYYMMDD-HHMMSS.sql.gz > /tmp/vector-backup.sql

# Открывает распакованный SQL-файл в постраничном просмотрщике; выход — клавиша q.
less /tmp/vector-backup.sql
```

Для просмотра данных как таблиц восстановите копию только в отдельную тестовую PostgreSQL-базу и подключитесь к ней через pgAdmin, DBeaver или команду `psql`. Не восстанавливайте дамп в рабочую базу лишь для просмотра: это может перезаписать текущие записи.

## Обновление

```bash
./deploy/backup.sh /srv/vector-backups
git pull --ff-only
docker compose build app
docker compose up -d
docker compose logs --tail=100 app
```

Миграции применяются при старте. Для отката верните предыдущую версию исходников и используйте проверенный дамп.

## Контроль после запуска

- `/api/health` сообщает `status: ok` и `database: connected`;
- пароль отсутствует в ответах API;
- записи видны после перезагрузки и в другом браузере;
- в инструментах разработчика браузера при сохранении виден успешный запрос `PUT /api/entities/...`, а не только локальное изменение экрана;
- исполнитель видит только свои задачи, руководитель и администратор — все;
- вложения открываются после перезапуска контейнеров;
- в `docker compose logs app` нет ошибок;
- дамп создается и восстанавливается на тестовом контуре.

## Построчное пояснение команд развертывания

Ниже приведены те же команды первого развертывания, но каждая строка снабжена комментарием. Команды выполняйте последовательно: комментарии, начинающиеся с `#`, вводить не нужно.

### 1. Подготовка операционной системы

```bash
# Обновляет локальный список доступных пакетов из репозиториев Ubuntu/Debian.
sudo apt update

# Устанавливает сертификаты, curl для скачивания, и Git для получения обновлений проекта.
# Ключ -y автоматически подтверждает установку пакетов.
sudo apt install -y ca-certificates curl git

# Скачивает официальный установочный скрипт Docker по HTTPS в временный файл.
# -f завершает команду при HTTP-ошибке, -s убирает служебный вывод,
# -S показывает ошибку при -s, -L следует за перенаправлениями.
curl -fsSL https://get.docker.com -o /tmp/get-docker.sh

# Запускает скачанный скрипт с правами администратора и устанавливает Docker Engine.
sudo sh /tmp/get-docker.sh

# Добавляет текущего пользователя SSH в группу docker.
# После повторного входа можно будет запускать Docker без sudo.
sudo usermod -aG docker "$USER"
```

После последней команды закройте SSH-сессию и подключитесь снова. Затем убедитесь, что Docker и Compose доступны:

```bash
# Показывает установленную версию Docker Engine.
docker --version

# Показывает версию Docker Compose plugin.
docker compose version
```

### 2. Размещение исходников на VPS

```bash
# Создает каталог для приложения в /opt; флаг -p не выдает ошибку, если он уже существует.
sudo mkdir -p /opt/vector

# Передает владение каталогом текущему пользователю, чтобы не работать с проектом от root.
sudo chown -R "$USER":"$USER" /opt/vector

# Переходит в каталог развертывания. Последующие команды надо запускать именно отсюда.
cd /opt/vector

# Клонирует репозиторий в текущий каталог.
# Замените URL на адрес вашего репозитория; не добавляйте точку в конце команды.
git clone ВАШ_URL_РЕПОЗИТОРИЯ .
```

Если проект передается архивом или через SFTP, вместо `git clone` загрузите в `/opt/vector` все файлы проекта, включая `compose.yaml`, `Dockerfile`, папки `server`, `src`, `deploy` и файл `.env.server.example`.

### 3. Настройка секретов

```bash
# Создает рабочий файл переменных окружения .env из безопасного шаблона.
cp .env.server.example .env

# Генерирует случайную строку длиной 36 байт в кодировке Base64.
# Скопируйте результат в значение COOKIE_SECRET файла .env.
openssl rand -base64 36
```

Откройте `.env` в редакторе и задайте значения:

```dotenv
# Сильный пароль PostgreSQL. Не используйте этот пример как реальный пароль.
POSTGRES_PASSWORD=замените-на-длинный-случайный-пароль

# Секрет для подписи сессий: вставьте результат openssl rand -base64 36.
COOKIE_SECRET=вставьте-сгенерированную-случайную-строку

# До настройки HTTPS cookie допускается передавать по HTTP только для первой проверки.
COOKIE_SECURE=false
```

Файл `.env` содержит секреты: не отправляйте его в Git, мессенджеры или публичные архивы.

### 4. Первый запуск контейнеров и проверка

```bash
# Собирает образ приложения при необходимости и запускает сервисы в фоне.
# -d означает detached: терминал сразу вернется к приглашению командной строки.
docker compose up -d --build

# Показывает состояние контейнеров. У app и postgres должен быть статус running/Up.
docker compose ps

# Выводит последние 100 строк журнала API-контейнера.
# По ним проверяются запуск миграций и успешное подключение к PostgreSQL.
docker compose logs --tail=100 app

# Запрашивает локальную проверку здоровья через Nginx-контейнер.
# Ожидаемый ответ содержит status: ok и database: connected.
curl http://127.0.0.1:8080/api/health
```

`127.0.0.1` означает «только этот сервер»: порт 8080 не доступен напрямую из интернета. Внешний доступ дает системный Nginx на портах 80 и 443.

### 5. Подключение системного Nginx и сертификата

```bash
# Обновляет индекс пакетов перед установкой Nginx, Certbot и firewall.
sudo apt update

# Устанавливает веб-сервер Nginx, клиент Let's Encrypt, его модуль для Nginx и UFW.
sudo apt install -y nginx certbot python3-certbot-nginx ufw

# Копирует подготовленную конфигурацию сайта Vector в каталог доступных сайтов Nginx.
sudo cp deploy/vector-vps.nginx.conf /etc/nginx/sites-available/vector

# Меняет служебный домен vector.example.ru на ваш реальный домен в копии конфигурации.
# ВАШ.ДОМЕН укажите без https:// и без завершающего слеша.
sudo sed -i 's/vector.example.ru/ВАШ.ДОМЕН/g' /etc/nginx/sites-available/vector

# Создает символическую ссылку, которая включает сайт в конфигурацию Nginx.
sudo ln -s /etc/nginx/sites-available/vector /etc/nginx/sites-enabled/vector

# Проверяет синтаксис всей конфигурации Nginx. При ошибке следующую команду не выполняйте.
sudo nginx -t

# Перечитывает конфигурацию без остановки уже работающего Nginx.
sudo systemctl reload nginx

# Получает сертификат Let's Encrypt, добавляет HTTPS-настройки и редирект HTTP → HTTPS.
# Замените ВАШ.ДОМЕН на тот же домен, который указан в DNS и конфигурации Nginx.
sudo certbot --nginx -d ВАШ.ДОМЕН
```

Перед запуском Certbot в DNS должна существовать запись `A` для домена, указывающая на публичный IPv4 VPS. Порт 80 также должен быть доступен снаружи.

После успешного HTTPS измените в `.env` `COOKIE_SECURE=true`, затем примените настройку и проверьте автоматическое продление:

```bash
# Перезапускает контейнеры с новым значением COOKIE_SECURE из файла .env.
docker compose up -d

# Имитирует продление сертификата без изменения действующего сертификата.
sudo certbot renew --dry-run
```

### 6. Firewall

```bash
# Разрешает SSH согласно профилю OpenSSH, чтобы не потерять доступ к VPS.
sudo ufw allow OpenSSH

# Разрешает входящие HTTP (80) и HTTPS (443) по профилю Nginx Full.
sudo ufw allow 'Nginx Full'

# Включает firewall. Подтвердите действие, если UFW попросит подтверждение.
sudo ufw enable

# Показывает итоговые правила и их состояние.
sudo ufw status
```

### 7. Резервная копия базы

```bash
# Делает скрипт резервного копирования исполняемым.
chmod +x deploy/backup.sh

# Создает сжатый SQL-дамп PostgreSQL в указанном каталоге.
# Каталог /srv/vector-backups должен существовать и быть доступен текущему пользователю.
./deploy/backup.sh /srv/vector-backups
```

Если каталога еще нет, создайте его один раз:

```bash
# Создает каталог для резервных копий и все недостающие родительские каталоги.
sudo mkdir -p /srv/vector-backups

# Назначает текущего пользователя владельцем каталога для запуска backup.sh без sudo.
sudo chown "$USER":"$USER" /srv/vector-backups
```

Проверка восстановления выполняется **только на отдельном тестовом контуре**, потому что команда записывает данные в базу:

```bash
# Распаковывает выбранный SQL-дамп в поток и передает его psql внутри контейнера postgres.
# -T отключает псевдотерминал, -U vector задает пользователя БД, -d vector — имя базы.
gunzip -c /srv/vector-backups/vector-YYYYMMDD-HHMMSS.sql.gz | docker compose exec -T postgres psql -U vector -d vector
```

### 8. Безопасное обновление версии

```bash
# Создает резервную копию перед любым обновлением кода или миграций.
./deploy/backup.sh /srv/vector-backups

# Загружает изменения только как fast-forward; команда остановится при локальных конфликтах.
git pull --ff-only

# Пересобирает только образ API-приложения с новым кодом.
docker compose build app

# Пересоздает нужные контейнеры в фоне, сохраняя данные volume PostgreSQL.
docker compose up -d

# Показывает последние 100 строк журнала приложения для контроля миграций и ошибок запуска.
docker compose logs --tail=100 app
```

После обновления откройте `https://ВАШ.ДОМЕН/api/health`, затем войдите в приложение и проверьте создание, редактирование, удаление и отображение записей после перезагрузки страницы.
